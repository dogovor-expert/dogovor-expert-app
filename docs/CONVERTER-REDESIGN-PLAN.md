## 4. Ограничения, которые нельзя нарушать

1. **Не выдумывать цифры.** В коде **нет лимита размера файла** (нет `maxSize`/`MAX_FILE`/константы
   в МБ). «45 МБ» из шаблона — выдумка дизайна. Публиковать такое на юридическом сайте нельзя.
2. Реальные и проверяемые версии движков брать из `package.json`:
   `pdf-lib ^1.17.1`, `pdfjs-dist ^6.2.108`, `tesseract.js ^7.0.0`, `docx ^9.7.1`,
   `@pdf-lib/fontkit ^1.1.1`, `react-to-print ^3.3.0`.
3. Утверждение «0 файлов на сервере» держать только после повторной проверки,
   что ни один из 15 инструментов не постит файл.
4. `Highlight.tsx` — это поисковый хайлайт (`text` + `query`), для H1 не подходит.
   Нужен отдельный микро-компонент или инлайновая разметка.
5. Рекламные слоты ограничены списком: `CONVERTER_FOOTER`, `CONVERTER_RELATED`,
   `LANDING_INFEED`. Новые слоты требуют новой переменной окружения.

## 5. Риски

- **Дублирование контента:** если FAQ хаба дословно повторит FAQ инструментов —
  получим thin content наоборот. FAQ хаба — про выбор инструмента и форматы, не про конкретный.
- **Раздувание `max-w-4xl`:** сейчас контент занимает ~850px из 1184px. Расширять до
  `max-w-6xl` надо осознанно, иначе строки станут слишком длинными.
- **Потеря функциональности:** `ConverterHub` держит выбранный инструмент в `useState`.
  Секции не должны его перемонтировать.
- **Регрессия по ширине:** на `/resume` уже есть баг горизонтального скролла (см. P0).
  Новые секции не должны его повторять.
