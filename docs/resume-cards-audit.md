## 0. Главное предупреждение: «эталон» непригоден как пиксельный референс

Это надо зафиксировать до всех остальных пунктов, иначе часть «расхождений» окажется не дефектами.

`ResumePreviewA4` получает `compact={true}` (ResumePage.tsx:79), но `compact` меняет **только** корневой `text-[10px]` и `rounded-lg` (ResumePreviewA4.tsx:42). Внутренние размеры заданы `sm:`-брейкпоинтами — это **медиазапрос вьюпорта, а не контейнера**, поэтому на десктопе (≥640px) внутри карточки 220px включаются:

|---|---|---|
| Имя | `sm:text-3xl` | **30px** |
| Отступы страницы | `sm:p-8` | **32px** × 4 |
| Фото exec / sidebar / base | `sm:h-20` / `sm:h-24` / `sm:h-22` | **80 / 96 / 88px** |
| Колонка-сайдбар | `sm:grid-cols-[1fr_14rem]` / `[15rem_1fr]` | **224 / 240px** при ширине карточки 220px |
| Рамка контента | `shadow-2xl` + `rounded-lg` | — |

То есть в эталоне рендерится **полноразмерный документ 794px в бокс 220px с `overflow-hidden`**: сайдбар шире самой карточки, горизонтальный контент срезан, имя 30px в колонке 156px. Превью в эталоне нечитаемо by design — это и есть причина, по которой `rc-*` написан заново (комментарий в `resumeCardCss.ts`:4–7).

**Вывод:** корректным числовым референсом для масштаба является не эталон, а документный CSS `sampleCss.ts` (794px) с коэффициентом **k = 220/794 = 0.277**. ## 1. Пропорции A4 и «лист обрезается снизу»

**Эталон:** `aspectRatio: "1 / 1.414"` на корне, обёртка `w-[220px]` **без высоты**, тень `drop-shadow-lg` на всём листе 220×311, `shadow-2xl` + `rounded-lg` на самом листе. Обрезка происходит на внешнем контейнере `h-64 overflow-hidden p-4`.

**У нас:** `.rc{width:100%;aspect-ratio:1/1.414;overflow:hidden}` (без radius и тени), а обёртка в `catalog.tsx:82`:
```html
relative mx-auto h-full w-[220px] overflow-hidden rounded-[3px] border border-slate-200 bg-white drop-shadow-lg
```
`h-full` = **224px** (256 − 2×16). Лист = 220×311. Видимая полоса = **224/311 = 72%**, срезано 87px.

**Дефекты:**

1. **Рамка и тень навешены на обрезанный бокс, а не на лист.** `border` + `rounded-[3px]` + `drop-shadow-lg` рисуют горизонтальную линию и скруглённые нижние углы ровно на линии среза. Визуально карточка выглядит как короткий документ 220×224, а не как верх страницы. В эталоне тень и `rounded-lg` идут по контуру полного листа 311px — срез читается как «продолжение вниз».
   **Правка:** убрать из обёртки `h-full overflow-hidden rounded-[3px] border bg-white drop-shadow-lg`, оставить `relative mx-auto w-[220px] transition-transform duration-500 group-hover:scale-105`; перенести на `.rc`:
   `border-radius:3px; box-shadow:0 12px 28px -8px rgba(15,23,42,.22), 0 2px 6px -2px rgba(15,23,42,.10)`. Срез выполнит внешний `<a>` (`overflow-hidden h-64 p-4`).

2. **87px (28%) листа не видно — но композиция под это не выведена.** Ни один блок не привязан к видимой полосе 224px. Прямое следствие в `rc-side`/`.rc-legal`: `.rc-foot{...margin-top:auto}` прижимает «Dogovor.expert · 2026» к низу 311px → **футер не виден ни в одной карточке** (плюс он есть только в 2 из 10 шаблонов). Аналогично языки в base-семействе.

3. **Разные проценты обрезки в каталоге и в drawer.** Каталог: 220×311, окно 224px → 72.0%. Drawer (`builderCss.ts:136–137`): `.rvb-tcard-th{height:186px}`, ширина карточки = (420 − 44 − 14)/2 = **181px** → лист 181×256, окно 186px → 72.7%. Расхождение невелико, но `.rvb-mini` — `position:absolute;top:0;left:0` **без центрирования и без `width`**; при `width:100%` внутри абсолютного контейнера без ширины ширина считается через shrink-to-fit. Работает, но хрупко.
   **Правка:** `.rvb-mini{position:absolute;inset:0;display:flex;justify-content:center}`, `.rvb-mini .rc{width:181px;flex:none}` — убрать зависимость от shrink-to-fit.

4. **Жёсткий срез без маски.** На фоне сетки 20px срез читается как «конец листа». Ни в эталоне, ни у нас нет индикации продолжения, но у нас полоса 224px режет **посреди ряда чипов** (см. §6).

## 11. Бюджет видимой полосы (сводный план подгонки под фолд 224px)

Видимая полоса каталога — **224px** (72% листа). Композиция должна укладываться в неё, а не в 311px. Проверка текущей base-карточки (демо-профиль «продажи»):

```
12  padding-top
+45 topline: имя 18px*1.2=21.6 + роль 2×8.5*1.5=25.5 + mt2 + pb7 + border 2   = 58
+61 контактная полоса (3 строки по 11.25 + gap 3 + padding 12 + mt7 + border 2)
+ 8 cols padding-top
────────────────────────── 139
main (112px): секция 21 → 160; опыт: title 12 + строка 25 + 2 буллета 27 = 64 → 224  ← ровно линия среза
rail (65px): секция 21 → 160; 6 чипов по 14 + 5 gap 3 = 99 → 259; качества 9+21+42 = 72 → 331  ← срезан на 107px
```
Итог: **буллеты второго места работы попадают ровно на срез, рельс обрезан на треть, языков и качеств не видно вообще.** Exec считается аналогично: шапка 100px (2-строчная роль) → остаётся 124px, рельс exec 103 + 50 = 153 → обрезан на 29px.

**Целевой бюджет (предложение):**

| Секция | Сейчас | Цель | Правка |
|---|---|---|---|
| Шапка base (имя+роль) | 58px | **40px** | роль `-webkit-line-clamp:1` (13px), имя 17px |
| Контактная полоса | 61px | **26px** | 2 контакта, 2 строки по 11.25 + gap 3, `padding:5px 0`, `margin-top:6px` |
| Отступ до колонок | 8px | 8px | — |
| Опыт (main) | 64px | **48px** | 1 буллет вместо 2 (`rcExp1`: `.slice(0,1)`), `rc-xp-b li{margin-top:0}` |
| Рельс: навыки | 120px | **37px** | 4 чипа @8px (16px высота) → 2 строки |
| Рельс: качества | 72px | **0px** | Убрать из карточки (в документе оставить) |
| Рельс: языки | 50px | **32px** | 2 языка, 1 строка на язык |
