## 0. P0 — слом полей листа у 7 из 10 шаблонов (НАЙДЕН И ИСПРАВЛЕН 30.09)

Первоначальный вывод аудита «шаблоны в превью рендерятся корректно» был **ошибочным**: замеры
снимались по пересечениям/обрезаниям, а не по привязке контента к краю листа. Жалоба при проверке
скриншотом подтвердилась.

**Симптомы** (скриншот шаблона Data & Engineering): имя, лид-абзац, контактная полоса и обе колонки
прижаты вплотную к краю A4 — полей страницы нет, документ выглядит «выдавленным» за формат.

**Корень:** в `src/lib/resume/sampleCss.ts`

```css
.smp.doc { padding: 0 }              /* строка 17 — специфичность 0-2-0, нужна, чтобы
                                        отменить legacy .a4 .doc{padding:54px 56px} */
.smp-base { padding: 34px 40px 40px } /* строка 101 — специфичность 0-1-0 → ПРОИГРЫВАЕТ */
```

`.smp.doc{padding:0}` перебивал `padding` у `.smp-base` — computed padding = `0px`, `.smp-top x=0`.
Пострадали все 7 `smp-base`-шаблонов: tech-indigo, classic-legal, nordic-minimal, creative-coral,
junior-launch, corporate-slate, data-mono. Не пострадали executive-navy (`smp-exec`, паддинги на
`.smp-hd`) и modern-emerald / legal-counsel (`smp-side`, паддинги на `.smp-bar`/`.smp-page`).
Баг-источник — коммит `8fc4048` (27.09, эталонные макеты): оба правила появились вместе.

**Фикс** (`sampleCss.ts:101`, проверен живыми замерами):

```css
.smp.smp-base { padding: 34px 40px 40px; display: flex; flex-direction: column }  /* 0-2-0, позже в источнике → выигрывает */
```

**Верификация:** `computedPadding: "34px 40px 40px"`, `.smp-top` x=40 y=34 w=714 (794−80 ✓);
перегон диагностики всех 10 шаблонов: overlaps=0, probs=0, полоса контактов сдвинулась y=158→192
(+34 = восстановленный padding-top). Снимки до/после: `template-diag-before/` vs `template-diag/`.
`tsc --noEmit` чистый.

**Методический вывод для аудита:** x-snap-гистограмма (`rvh1 @0,0 794x30` — имя во всю ширину листа)
содержала сигнал слома, но был прочитан как «сетка держится». Замер отступа первого контентного
блока от края `.a4` обязателен в проверочном списке.

## 2. Блок предварительного просмотра (stage) — глубокий разбор

Анатомия: `.rvb-stage` (сцена, точечный фон `radial-gradient`) → `.rvb-stagebar` (56px, blur-тулбар)
→ `.rvb-scroll` (scrollable, `overscroll-contain`, `align-items:center`) → `.rvb-scaler` (794·scale × docH·scale)
→ `.a4` (794×1123, `transform: scale()`, `transform-origin: top left`, тень `0 1px 1px + 0 2px…`)
→ `.rvb-pagelabel` (имя шаблона слева, «A4 · 210×297 мм · N стр.» справа).

### 2.1 P0 — тулбар переполнен: зум-группа уходит за пределы видимости

> **ИСПРАВЛЕНО 30.09.2026** (вариант «б»): `.rvb-stagebar` получил `flex-wrap` + `min-height:56px` —
> на 1440 две аккуратные строки (действия / зум справа, barH 99px), на 1280 и 1120 — строки упаковываются,
> scrollW == clientW на всех ширинах, hit-test каждой контролы попадает в неё саму. Подробности §5 №1, §7.

Замер на live (1440×900, студия `#studio`) **до фикса**:

| Элемент | Геометрия | Статус |
|---|---|---|
| `.rvb-stagebar` | clientW 652px, scrollW **820px** | переполнение +168px |
| `.rvb-qwrap` (Качество 120px) + «Шаблоны» 123 + «DOCX» 96 + «PDF» 140 | укладываются в 527px | ок |
| `.rvb-zoom` (Лист/Ширина/100% + −/+/%) | left 537 → right **820** при bar 652 | **clipped** |

`.rvb-app` имеет `overflow:hidden` и не даёт зум-группе выехать наружу, и не даёт тулбару скроллиться —
кнопки «Уменьшить/Увеличить масштаб» и часть пресетов **недостижимы мышью** (hit-test в центре `.rvb-zoom`
попадает в панель редактора). При 1280 хуже (bar 492px), при 1120 — критично (bar 332px: из зума видна лишь
половина пресетов). Комментарий в `builderCss.ts:91` фиксировал overflow при сцене 812px (убрали имя
шаблона в pagelabel) — но при фактическом desktop-раскладке (editor + stage) сцена всего 652px, и overflow вернулся.

Фикс-варианты (по возрастанию инвазивности):
a) `.rvb-zoomset` превратить в «…»-меню под 900px сцены; б) stagebar → 2 строки (actions / zoom);
в) `overflow-x:auto` + `scroll-behavior` на stagebar; г) спрятать «Ширина/100%» в поповер по тапу на %.

### 2.2 P1 — «лента» вместо страниц: пагинация превью не показывает разрывы

> **ИСПРАВЛЕНО 30.09.2026** радикальнее пунктира: превью теперь НАРЕЗАНО НА ОТДЕЛЬНЫЕ ЛИСТЫ A4 —
> каждый лист это `.a4` с клоном контента (`top:-1123·i`), между листами физический зазор 16px и тени
> «стопки» (стиль PDF-вьюеров). Замер: 14300 симв. → 6 листов × 1123px, зазоры 16px, scaler 6818px,
> pagelabel «6 стр.» = число листов. См. §5 №3, §7.

Сценарий: в поле «Кратко о себе» подставлено 14 300 символов (обход maxLength — тестовый).
Результат: `.a4` превращается в одну непрерывную полосу **6220px** высотой; в `rvb-pagelabel` честно пишется
«A4 · 210 × 297 мм · **6 стр.**», но визуально страниц никак нет: ни линий разрыва, ни теней «стопки»,
ни нумерации. Пользователь видит «вечный» лист без единого маркера формата A4.
Разрывы страниц есть только в экспорте PDF (`resumePdf.ts` — `newPage()`), т.е. превью ≠ результат пагинации.
Минимальный фикс: пунктирная линия + лёгкий зазор между «страницами» кажд��е 1123px (`docH` уже считается).

### 2.3 P1 — вертикальная центровка листа и скролл

> **Статус 30.09.2026:** дефолтный зум изменён на «Ширина» (76% при сцене 652px) — см. §5 №7;
> «Лист» остался доступен кнопкой (46–50%, cap 0.695).

`.rvb-scroll` центрирует лист (`align-items:center`). При `docH × scale > высоты сцены` лист «прилипает» и
скролл работает — ок; но при fit-масштабе **50%** (замер: `zv` = 50%, cap 0.695) шрифт 13px на листе читается
как 6.5px. Состояние по умолчанию на 1440 ноутбуке — «нечитаемый макет»; ждать, что пользователь найдёт
«100%» (который ещё и в обрезанной зум-группе, §2.1) — оптимистично. Рекомендация: fit по ширине как дефолт
на stage ≥ 500px, а «Лист» — как опция.

### 2.4 Состояния и микровзаимодействия (замеры)

- **Зум**: шаги через `ZOOM_STEPS`; fit clamp 0.2…0.695 (высота) / 0.2…1.25 (ширина). Логика `ResizeObserver`
  (+ учёт резерва 200px под мобильные табы) — грамотно, edge-cases задуманы.
- **Индикатор зума** `.zv`: 12px/700 tabular-nums — хорошая деталь; но `aria-live="off"` — скринридер не
  услышит смену масштаба (мелочь).
- **Поповер качества** `.rvb-qpop`: 300px, radius 16, shadow `0 10px 25px`, 10 чек-пунктов; выполненные —
  `line-through` + зелёная галка. Геометрия заслуживает 4; контраст галки 3.77:1 — минус (§1.4).
- **Drawer шаблонов**: мини-превью `.rvb-mini` 249×352 (scale-трансформ), фильтры-чипы `.rvb-fchip` 31–32px
  высоты (ниже тап-нормы 40px на тач), акцент-доты `.rvb-accent-dot` 30×30px с `aria-label` — уровень выше
  среднего по a11y; но 7.5–8px текст **внутри** миниатюр — это рендер макета, не UI: ок.
- **Esc**: закрывает drawer и поповер + `inert` на скрытом drawer — правильно.
- **Мобильные табы** «Редактор / Просмотр» (390px, ширина без overflow) — правильный паттерн для билдера;
  на вкладке «Просмотр» те же проблемы тулбара (§2.1), усугублённые: «Шаблоны/DOCX/PDF» сжаты до 36–38px
  (только иконки из-за `hidden sm:inline` — ожидаемо), зум 28×28px, fit = 37% — текст листа 4.8px.

### 2.6 Верность WYSIWYG между превью и экспортом

Три независимых рендерера на одних данных:

| Канал | Что рендерит | Типографика | Пагинация |
|---|---|---|---|
| Превью `.a4` | `buildResumePreviewHtml` (flex/grid, RESUME_CSS + sampleCss) | Inter 13px | «лента» без разрывов |
| DOCX | `buildResumeDocHtml` (таблицы, inline-styles) → `parseHtmlToDocx` | Arial / Times New Roman, pt | word `page-break-inside` |
| PDF | `renderResumePdf` (pdf-lib, свой `STYLES`) | встроенные шрифты, правила вручную | `newPage()` |

Это ожидаемая архитектура для Word-совместимости (DOCX без flex/grid — осознанный выбор, см. комментарии
`resumeDocx.ts:1-13`), но визуально превью и DOCX — разные документы: pt/px, Arial/Inter,
фото, чипы и бордеры превью не переносятся 1:1. Пользователь, выбравший «Tech Pro 2026», в Word получит
другой по ритму документ. Снизить разрыв: оверлей-предупреждение «DOCX — офисная версия макета» +
скриншот-галерея готового DOCX в drawer.

### Наблюдения

1. **Контент занимает 43–64% высоты A4** при демо-данных (488–724px из 1123px). Ок для шаблона с SAMPLE,
   но ни один из документов не «дышит» до конца страницы — у Modern Sidebar/Legal Counsel низ страницы
   пустует наполовину. Визуально это читается как «пустое резюме».
2. **Снапы X чистые**: executive 2-колонка 64%/36% (819px шов), modern 33%/66% (428px шов), single — 13px
   поля. Модульная сетка выдержана во всех 10.
3. **Шкала pt**: заголовки 20–22pt, H2 12pt (с border-bottom акцентом), тело 10.5pt (14px), метаданные
   9.5pt (12.7px) — градация читаемая; размеры достигают минимума 9.5pt — порог печати выдержан.
4. **Упрощения против превью** (ожидаемы, но их стоит мониторить):
   - `smp-chip`-облака навыков → в DOCX «НАВЫКИ» одной строкой через запятую;
   - цветные строки компаний → `« — Компания»` акцентным цветом (сохранено ок);
   - таймлайн-точки/фото-рамки → `expDots`-бордер слева 2pt (сохранено); фото в header сохраняется
     только для `photoInHeader` шаблонов.
5. **Защита от разрывов**: `page-break-inside:avoid` на блоках мест работы — правильно предугадано
   (осколок «заголовок без содержимого» в Word — классическая беда).
6. **Контраст в DOCX-разметке**: `#6b7280` на белом = 4.8:1 ✓, `#94a3b8` не используется (в отличие от превью —
   тут даты `#6b7280`, что лучше). Разрыв превью/DOC по контрасту метаданных — в пользу DOCX.
7. **modern-emerald / legal-counsel (sidebar)**: тёмная колонка `#059669`/`#1e3a8a`, белый текст и
   `#a7f3d0`/`#93c5fd` акценты — контраст 3.7:1+ для 12.7px bold заголовков колонки на зелёном — на грани AA
   (норма 4.5:1 для < 18.66px bold). Светлый `sideAccent` на тёмном работает — ок для заголовков, не для тела.
8. **Creative Accent**: 1px-стрип сверху (`font-size:1pt;line-height:1pt`) — технический хак, отсекается
   аудитором как «tiny», по факту норма для Word-стрипов.

## 4. Что оценивается высоко
