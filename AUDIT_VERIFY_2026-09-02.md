### 2.1.Истинная причина 186 ошибок ESLint

Список `ignores` в `eslint.config.mjs` содержит только `src/lib/workers/**`. Каталог `scripts/` в него **не включён**, поэтому Node CLI-скрипты проверяются браузерными правилами:

```
25  scripts/setup-telegram-webhook.mjs
19  scripts/vault-crypto-test.mjs
15  scripts/diag-yandex-connect.mjs
14  scripts/vault-e2e.mjs
12  scripts/check-redesign.mjs
12  scripts/print-verify.mjs
... итого 176 ошибок в scripts/ + 3 в audit/walkthrough.spec.ts
```

**Решение — один блок в конфиге, ~10 минут:**

```js
{
  files: ['scripts/**/*.mjs', 'audit/**/*.ts'],
  languageOptions: {
    globals: { process: 'readonly', Buffer: 'readonly', __dirname: 'readonly',
               console: 'readonly', fetch: 'readonly', URL: 'readonly' },
  },
}
```

## 4. Блокирующие дефекты модуля подписи

### K1 — PDF не распознаётся как подписанный

`src/lib/embedSignature.ts` (51 строка) создаёт словарь подписи и кладёт его в **несуществующий ключ каталога**:

```js
const catalog: any = pdfDoc.catalog;
catalog.set(signatureDict, "CAdES_Signature");   // ← такого ключа нет в PDF spec
```

Чего нет, но должно быть по спецификации:

| Требование | В `embedSignature.ts` |
|---|---|
| `/ByteRange` — какие байты покрыты подписью | ❌ отсутствует |
| `/AcroForm` + поле `/FT /Sig` | ❌ отсутствует |
| Зарегистрированный `Filter` | ❌ `"CryptoPro PDF"` — выдуман |
| `/Contents` по месту с сохранением смещений | ❌ дописывается в конец |

Итог: ни Adobe, ни Foxit, ни КриптоПро PDF, ни НЭП не увидят подпись. Документ откроется как **неподписанный**.

**А в проекте уже есть корректная реализация** — `src/lib/embedPades.ts` (204 строки):
- `preparePAdESPlaceholder()` — реальный `/ByteRange` с вычисленными значениями, `/Contents`-плейсхолдер нужной длины
- `AcroForm` + `FT: 'Sig'`
- `SubFilter: 'adbe.pkcs7.detached'`
- `embedCms()` — вставка CMS без сдвига смещений
- юнит-тесты: `src/lib/__tests__/embedPades.test.ts`
- уже используется в `UKEPSigner.tsx`

Агент её не нашёл и написал поверх «упрощённую версию», которая не работает.

### K2 — подпись покрывает не те байты

```js
const signatureBase64 = await signPdfWithCryptoPro(pdfBytes, ...);  // подпись исходных байт
const signedPdfBytes  = await embedSignatureSimple(pdfBytes, signatureBase64, ...);  // файл пересобран
```

`pdf-lib` пересериализует документ и дописывает словарь — итоговые байты отличаются от подписанных. Отсоединённая CMS не соответствует содержимому файла.

### K3 — падение на любом реальном документе

`SignDialog.tsx:149`:
```js
String.fromCharCode.apply(null, Array.from(signedPdfBytes))
```
`Function.prototype.apply` падает с `RangeError: Maximum call stack size exceeded` на массивах больше ~65–130 тыс. элементов. Типовой договор — 200 КБ–1 МБ, то есть **200 тыс.–1 млн элементов**. Шаг «сохранить подпись на сервере» будет падать всегда.

Собственный хелпер проекта `uint8ToBase64` (`signCryptoPro.ts:673`) делает то же самое **чанками по 0x8000** — надо просто переиспользовать его:

```js
const signedPdfBase64 = uint8ToBase64(signedPdfBytes);
```

### K4 — `/api/sign/accept` не проверяет владельца

```js
const admin = createAdminClient();   // service role — RLS обходится
...
document_id: documentId,             // принадлежность документа нигде не проверена
user_id: user.id,
```

`prepare` проверку делает (`doc.user_id !== user.id` → 403), `accept` — нет. Любой авторизованный пользователь может создать запись о подписи чужого документа. RLS не спасает: admin-клиент его обходит.

Плюс `documentId` не валидируется как UUID и подставляется в путь:
```js
const storagePath = `signed/${user.id}/${documentId}-${timestamp}.pdf`;
```

### K5 — «проверка» не проверяет подпись

`/api/sign/[id]/verify` сравнивает `sha256(файл из Storage)` с хэшем, посчитанным из **этого же файла** при сохранении. Это тавтология: совпадение гарантировано, пока файл не повреждён в хранилище.

Не делается вообще ничего из того, что делает проверку проверкой:
- разбор CMS / CAdES-структуры
- проверка цепочки сертификатов
- CRL / OCSP — отзыв сертификата
- проверка метки времени RFC 3161

При этом ответ содержит:
```js
message: "Хэш документа совпадает — документ не изменён после подписания"
```

Пользователь видит «проверено» и считает подпись юридически действительной. По 63-ФЗ это прямая зона ответственности: тот, кто менял файл и имел доступ к БД, обновит и хэш — проверка промолчит.

### K6 — `isSameOrigin` на GET ломает обычное скачивание

Браузер не отправляет `Origin` при переходе верхнего уровня. `isSameOrigin` возвращает `false` при отсутствии Origin → прямая навигация на `/api/sign/[id]/download` даёт **403**. Работает только fetch с того же origin; «открыть в новой вкладке» — нет.

### K7 — действия обычных пользователей пишутся в админский аудит

Во всех четырёх роутах `logAdminAction({ adminId: user.id, ... })`. Таблица админского аудита засоряется действиями рядовых пользователей, а отчёты, предполагающие что `adminId` — администратор, начнут врать.

### K8 — неограниченное тело запроса

`accept` читает и декодирует base64 целиком в память и лишь потом проверяет 50 МБ. Нужен отказ по `Content-Length` до чтения.
