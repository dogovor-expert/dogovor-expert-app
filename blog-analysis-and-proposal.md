## 2. Оценка качества текущих статей

**Сильные стороны (все 15 статей):**
- Высокий юридический уровень: прямые ссылки на нормы — ст. 687, 702, 779, 720, 808
  ГК РФ; ст. 224, 122, 333.19 НК РФ; ст. 19.1, 15 ТК РФ; 422-ФЗ о НПД; 193-ФЗ; 229-ФЗ.
- Структура «Коротко → пошагово → риски → FAQ» — дружелюбна к читателю и к SEO.
- FAQ по 5 вопросов — закрывают типовые запросы (годится для schema.org FAQ).
- Каждая статья ссылается на 1–3 шаблона документов (`relatedDocs`) — без битых ссылок:
  все id существуют в `LEGAL_TEMPLATES`.
- Хорошие мета-заголовки с годом (2026), описания строго 140–160 символов.
- Нет спама, продакшн-текст, емкие формулировки.

**Наблюдаемые проблемы / точки роста:**
1. **Перекос по категориям.** «авто» — всего 1 статья, «финансы» — 3, «право» — 2.
   При этом в каталоге 39 шаблонов по авто и 31 по финансам — тематический потенциал
   не раскрыт, а у сервиса (ДКП, автоподбор, ОСАГО) аудитория автомобильная.
2. **Все даты одинаковые (2026-08-20)** — блог выглядит «залитым за раз». Желательно
   «размазать» даты, чтобы не пугать поиск и читателя.
3. **Нет «ЕАТ»-блоков** (автор, юрист, дата обновления) — хотя Article-разметка автор
   = организация. Можно усилить доверие.
4. **Нет статьи-«хаба» / внутриблоговых перелинковок по категориям** (только «Читайте
   также» по той же категории, максимум 3).
5. **Невысокие позиции по «низкочастотным коммерческим» запросам**, которые прямо
   связаны с шаблонами: «как составить договор дарения», «договор купли-продажи
   квартиры», «алименты», «брачный договор» и т.п.

> Итог: качество существующих статей — высокое. Основная задача — **расширить охват
> тем под реальные шаблоны и запросы**, сбалансировать категории и дать больше
> семантики под SEO.

## 5. Технические рекомендации по реализации

1. **Добавление** — только в `src/data/blog/posts.ts`: вставить 20 новых объектов
   `BlogPost` в массив `BLOG_POSTS` (порядок внутри массива = порядок в списке блога).
2. **Уникальность slug** — все предложенные slug не пересекаются с текущими 15.
3. **relatedDocs** — только id из `LEGAL_TEMPLATES` (проверено по каталогу, все
   указанные существуют). Если какой-то id не найдётся, страница просто не покажет
   блок документов — но мы связываем только существующие.
4. **Sitemap и robots** — обновятся автоматически из `BLOG_POSTS`, отдельно ничего
   не менять.
5. **SSG** — новые статьи попадут в сборку без изменений кода страниц
   (`/blog/[slug]` уже генерирует по `BLOG_POSTS`).
6. **Даты** — рекомендую ставить даты с шагом (например, не все 2026-08-20), чтобы
   блог выглядел живым; финальные даты согласуем.
7. **После добавления**: `npm run build` + `npx tsc --noEmit`; затем по желанию
   коммит + push (Vercel автодеплой).
